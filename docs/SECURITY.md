# Private key handling

acme-lan's guiding rule: **no private key material is stored in the database or on disk in
the clear**, with a single opt-in exception (device-push local key generation). Unencrypted
key material may pass *through* the service in memory, but it is not written to disk in the
clear.

## Where private keys come from, and where they go

| Flow | Private key | At rest? |
| --- | --- | --- |
| **ACME proxy** (certbot/acme.sh → acme-lan → upstream) | Generated by the *client*; only the CSR reaches acme-lan | acme-lan never sees it |
| **Device push, `csr_source=device`** (preferred) | Generated on the *device*; only the CSR reaches acme-lan | acme-lan never sees it |
| **Device push, `csr_source=local`** (opt-in, UI warns) | Generated by acme-lan | Stored **encrypted** (Fernet / Key Vault / Vault); `key_storage` records where |
| **Upstream ACME account key** | Generated by acme-lan | Stored **encrypted** in the DB; **in-memory only** (regenerated per process) if no secret key is set — never a plaintext file |
| **Self-service TLS key** (admin UI / ACME endpoints) | Generated by acme-lan | Stored **encrypted**; materialized to an in-memory `memfd` for uvicorn — never a plaintext file. Requires `ACME_LAN_SECRET_KEY` |

The public certificate chain is written to disk (`self_cert_path`) — that's public and safe.

## Encryption

`ACME_LAN_SECRET_KEY` is a Fernet key (generate with
`python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`).
It encrypts, at rest:

- device credentials stored locally (`provider=local`),
- locally-generated device private keys,
- the upstream ACME account key,
- the self-service TLS key.

Remote providers (**Azure Key Vault**, **HashiCorp Vault**) can hold device credentials and
issued cert/key bundles instead of the local database, so those secrets never land in
acme-lan's storage at all.

## Serving TLS without a plaintext key on disk

Python's `ssl` module loads keys from file paths, so the self-service key is decrypted into
a Linux `memfd` (anonymous, RAM-backed) and uvicorn is pointed at `/proc/self/fd/<n>` — the
plaintext never touches persistent storage. On platforms without `memfd_create`, acme-lan
falls back to a `0600` temporary file and logs a warning.
